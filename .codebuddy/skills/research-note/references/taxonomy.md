# 研究笔记 · 字段取值规范

供 `research-note` skill 填写 `note.json` 时查用。**`seg` / `sub` 只影响笔记在研究工作台侧栏的归集范围，填错不会报错但会导致笔记归错节点**，请照抄下表。

## 1. industry（三个域）

| 值 | 含义 |
|---|---|
| `semiconductor` | 半导体 |
| `ai` | 人工智能 |
| `robotics` | 机器人 |

不属任一域的综合观点（如宏观策略、跨域比较）→ 留空 `null`。

## 3. companies（关联企业）

- **必须使用研究池内的企业简称**，与 `COMPANIES[].name` 完全一致（脚本会校验，不一致直接报错）。
- 一篇笔记可关联多家。**只要关联了企业，该笔记就会出现在对应企业的详情页「研究笔记」卡片**。
- 企业不在池内时：不要硬填。若该企业值得长期跟踪，应先把它纳入研究池，再回来写笔记。
- 查名字：在 `src/research/data.ts` 搜 `"name": "关键词"`，或运行脚本时依赖其校验报错提示。

## 4. tags（话题标签）

- 2–6 个，短词，不带 `#`（前端渲染时自动加）。
- 优先复用已有标签以形成聚合。当前常用：`先进封装`、`混合键合`、`键合设备`、`设备平台化`、`3D集成`、`HBM`、`Chiplet`、`硅光`、`CPO`、`薄膜铌酸锂`、`大基金`、`国产替代`、`存储涨价`、`热管理`、`金刚石散热`、`氮化铝`、`石墨烯导热`、`人形机器人`、`具身智能`、`AI算力`。
- 避免过长（>8 字）或过细（一次性人名/机构名）。

## 5. kind（笔记类型）

| 值 | 何时用 |
|---|---|
| `观点` | 从文章/研报中提炼的判断、趋势、投资逻辑 —— **「总结观点」默认用这个** |
| `纪要` | 调研、电话会、访谈的记录 |
| `资料` | 数据、事实、名单类沉淀（不含鲜明判断） |
| `研报` | 完整研报的归档笔记 |

## 6. occurred_at（内容日期）

- 指**内容本身的日期**（文章发布日 / 事件发生日），不是写笔记的日期，格式 `YYYY-MM-DD`。
- 页面按此字段倒序排列，并在卡片上显示。
